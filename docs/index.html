Web Expressive Documentation

Web Expressive is a toolkit built on web standards that simplifies and accelerates UI development for the web. It brings the design intent of Material 3 Expressive to HTML and CSS through design tokens, components, and adaptable layout patterns.

The toolkit is open source and available on GitHub.

Getting Started

Web Expressive helps you build performant and beautiful web applications with:

  • Zero-Runtime: Built with a standards-first approach using modern CSS (Container Queries, @scope, CSS Layers, Relative Colors) and native HTML, saving maximum performance for your app's logic.
  • Production-Ready Theming: 50+ built-in light/dark schemes, a full set of documented system tokens, 35 abstract shapes, configurable components with dedicated APIs, and instant theme-swapping with friction-free overrides.
  • Drop-in Modularity: Pick only what you need, from tokens to individual components, without adding bundle bloat or breaking existing workflows.

Installation via npm

Install the package in your project:

npm install web-expressive

Import the required stylesheets into your global CSS:

@import "web-expressive/core.css";
@import "web-expressive/schemes/alpha/fuchsia-tonal.css"; /* Replace with any of the available schemes. */
@import "web-expressive/components/button.css";         /* Optional: import only the components you use. */

Modular Imports

Web Expressive organizes design system resources into four modular imports categories: core, schemes, components, and shapes. Embed stylesheets in your HTML <head> via CDN or import them into CSS via npm.

Resource Stylesheet Requirement Description
Core core.css Required CSS reset and system tokens (typography, spacing, corners, motion, elevation).
Scheme schemes/[collection]/[scheme].css Required Color roles for light and dark modes. Single scheme recommended.
Components components/[component].css Optional Modular interactive components. Import only what you use.
Shapes shapes/clip-tokens.css Optional 35 Material 3 Expressive abstract shape clipping and masking paths.

Load core first, followed by your chosen scheme. Then add the components and shape tokens your page uses.

Theming

Theming is the architectural backbone of Web Expressive. It empowers products to express distinct visual identities without starting from scratch, while providing granular control over every color, corner, typeface, and layout dimension.

Theming Overview

Web Expressive theming is built on four structural pillars:

Pillar Mechanism What It Provides
1. Color Schemes Static stylesheets via light-dark() Instant swapping between 50+ curated color schemes with automatic dark and light modes.
2. Typeface Mapping @property registered reference tokens Decoupled font loading; map any brand font to the entire typescale with one token.
3. Density & Shape APIs Container style queries (--size-items, --shape-items, --width-items) Declaratively adjust component density, width, and corner roundness per container.
4. Zero-Friction Overrides CSS Cascade Layers (@layer design-system) Project styles override library rules naturally without specificity battles or !important.

Understanding Tokens in Web Expressive

Web Expressive exposes the full set of system tokens documented in this reference as CSS custom properties prefixed with --sys-*. These are the public tokens you use to build and style your interfaces.

In addition to system tokens, Web Expressive provides configuration custom properties that function as public component APIs. These include container style query properties (--size-items, --width-items, and --shape-items) to declaratively adjust component sizing, width, and corner rounding per container, as well as typeface configuration properties (--ref-typeface-*) to customize font families across the typescale.

Web Expressive also exposes its focus-ring motion tokens (--focus-ring-motion-spring and --focus-ring-motion-duration). Focus rings are a common interaction behavior across Web Expressive components, and these tokens are made available so you can apply the same spring outline behavior to your own custom components.

When inspecting components in browser DevTools, you will also see custom properties prefixed with --_*. These are private CSS custom properties used internally to build the components. Be cautious when overriding them, as incorrect overrides can break component styling.

Choosing a Scheme

A color scheme is a group of colors assigned to semantic roles, which are then mapped to UI elements. Web Expressive represents these roles as CSS custom properties with built-in support for light and dark modes through the native CSS light-dark() function. See a color scheme stylesheet example.

Web Expressive provides two parallel collections with identical filenames and CSS variable names. Switch between them anytime by adding or removing alpha/ in your import path.

Collection Import Path Based On Visual Explorer
Alpha (Default) schemes/alpha/[scheme].css Newer Android releases featuring richer, juicier color generation. Alpha Explorer
Standard schemes/[scheme].css Official Material Design 3 guidelines and Figma toolkit. Standard Explorer
  • Path Parity: Both collections share identical filenames and variable names. Swapping between them requires only toggling alpha/ in the stylesheet path.
  • Collection Differences: The collections differ in their variant families and baseline scheme. Single-color, dual-color, and monochrome schemes are identical across both collections.
  • Regular Updates: Both collections are regularly updated.

Preview all 50+ schemes live, test light and dark modes, and grab your import snippet instantly using the Alpha Schemes Explorer or the Standard Schemes Explorer.

Single vs. Multiple Schemes in One Document

To scope a secondary scheme to an isolated container, use the data-theme attribute:

<!-- Global scheme applies to main document -->
<button class="button">Global Primary</button>

<!-- Scoped secondary scheme on an isolated section -->
<section data-theme="fuchsia-tonal">
  <button class="button tonal">Scoped Fuchsia Action</button>
</section>

Caution: Scoping multiple schemes requires importing both scheme stylesheets. Use multiple schemes sparingly.

Handling Modes

Web Expressive features a unified theming engine where colors and elevation shadows adapt in perfect synchrony across light and dark modes.

1. Automatic System Adaptation (Default)

Out of the box, Web Expressive configures color-scheme: light dark; on html in core.css, while elevation tokens automatically invert their key and ambient shadow layers for dark surfaces using @media (prefers-color-scheme: dark).

Your application automatically honors the visitor's operating system preferences with zero configuration or JavaScript required.

2. Explicit Mode Control (Data Attribute or Class)

Native CSS color-scheme only manages color keywords and light-dark() calculations—it does not alter box shadows. To toggle or force modes, Web Expressive provides built-in mode selectors in core.css that update both color-scheme and elevation tokens in lockstep:

  • Light Mode: [data-mode="light"] or .light-mode
  • Dark Mode: [data-mode="dark"] or .dark-mode
<!-- Force Dark Mode on the entire page -->
<html lang="en" data-mode="dark">

<!-- Or via class -->
<html lang="en" class="dark-mode">

Tip (3-State Toggles): To restore automatic OS adaptation (system mode), simply remove the data-mode attribute (or mode class), or set data-mode="system"; the document naturally falls back to default color-scheme: light dark and responsive elevation shadows.

3. Scoped Island Theming (Subtree Overrides)

Mode selectors work on any element in your layout. To render an inverted dark card or sidebar inside an otherwise light page, apply data-mode="dark" or .dark-mode directly to that container. All child colors and elevation shadows switch locally: 

<!-- An inverted dark card inside a light document -->
<div class="card dark-mode">
  <h4>Featured Dark Card</h4>
  <button class="button tonal">Action</button>
</div>

Customizing Typefaces

Web Expressive decouples font loading from typography tokens, making font configuration clean, modular, and centralized.

In CSS, the font-family property combines specific font family names with a generic family fallback. Web Expressive separates these into two distinct custom properties: specific font names are set on --ref-typeface-* (which accepts only a comma-separated list of quoted strings, such as "Inter" or "Inter", "Arial", "Helvetica"), while the generic fallback is set on --ref-typeface-generic (such as sans-serif or serif). Because the initial value for --ref-typeface-generic is sans-serif, you only need to declare it if your typography requires a different generic family fallback.

Load your chosen web font using any provider (such as Google Fonts) or via @font-face definitions. For the typescale tokens to render accurately across all standard and emphasized styles, your loaded font family should include weights 400 (Regular), 500 (Medium), and 700 (Bold).

Important: All typeface customizations must be declared on the html selector (or :root) so typography tokens resolve correctly across the page. 

[html root custom properties]
 │
 ├─► (None Defined) 
 │   └─► Fallback to [--ref-typeface-generic] ("sans-serif")
 │
 ├─► [--ref-typeface-base] (Global Cascade)
 │   └─► Cascades down to ALL [--sys-typescale-*] & [--sys-typescale-emphasized-*] tokens
 │
 ├─► Baseline Role Splits:
 │   ├── [--ref-typeface-brand] ──────────► [--sys-typescale-* (Title Large ──► Display Large)]
 │   └── [--ref-typeface-plain] ──────────► [--sys-typescale-* (Label Small ──► Title Medium)]
 │
 └─► Emphasized Role Splits:
     ├── [--ref-typeface-emphasized-brand] ► [--sys-typescale-emphasized-* (Title Large ──► Display Large)]
     └── [--ref-typeface-emphasized-plain] ► [--sys-typescale-emphasized-* (Label Small ──► Title Medium)]

To change the font family for the full typography system, override the base variable:

html {
  --ref-typeface-base: "Open Sans";
}

To split the family by role, override the brand and plain references separately:

html {
  --ref-typeface-brand: "Inter"; /* Display, Headline, Title large */
  --ref-typeface-plain: "Open Sans"; /* Title small/medium, Body, Label */
}

Emphasized typography inherits from the brand and plain references by default, but you can override those families separately:

html {
  --ref-typeface-emphasized-brand: "Anton"; /* Display Emphasized, Headline Emphasized, Title large Emphasized */
  --ref-typeface-emphasized-plain: "Anton"; /* Title small/medium, Body, Label */
}

You can provide one or more fallback fonts, but all font names must be quoted:

html {
  --ref-typeface-base: "Inter", "Arial", "-apple-system", "BlinkMacSystemFont";
}

Use --ref-typeface-generic for the generic fallback. It defaults to sans-serif and accepts one unquoted value from the following list: serif, sans-serif, system-ui, monospace, cursive, fantasy, math. 

html {
  --ref-typeface-generic: cursive;
}

Tip: Prioritize changing --ref-typeface-base first. Only specialize roles if the design intent requires distinct visual weights or stylistic contrast.

To explore how Web Expressive maps custom properties to CSS font shorthands under the hood, read The Power of CSS Shorthands.

Managing Overrides

Web Expressive eliminates specificity battles. By utilizing CSS Cascade Layers, project styles override library tokens and components naturally without !important.

1. Built-in Cascade Layers (@layer design-system)

All Web Expressive rules are encapsulated within the design-system layer. For normal author declarations, unlayered styles take precedence over layered styles regardless of selector specificity: 

[ Unlayered User Styles ]  (Highest layer precedence for normal author declarations)
            │
            ▼
[ User Defined Layers ]    (e.g., @layer app, declared after design-system)
            │
            ▼
[ @layer design-system ]   (Web Expressive library defaults)

2. Adapting a Scheme (Role Overrides)

Override individual roles on html (or :root) to customize specific colors without editing the library:

html {
  --sys-color-error: light-dark(oklch(50% 0.18 29), oklch(83% 0.07 22));
  --sys-color-on-error: light-dark(oklch(100% 0 0), oklch(32% 0.11 28));
  --sys-color-error-container: light-dark(oklch(92% 0.03 23), oklch(42% 0.15 28));
  --sys-color-on-error-container: light-dark(oklch(25% 0.08 28), oklch(92% 0.03 23));
}

3. Typography Token Resolution

Web Expressive uses the CSS font shorthand exclusively for typescale tokens. Shorthand values resolve at the element where they are declared. Always declare --ref-typeface-* overrides on html (or :root) to ensure the entire typescale recalculates correctly.

Tokens Reference

Design tokens are the foundational building blocks of Web Expressive. They store visual attributes, including colors, typography, elevation, motion, spacing, and shapes, as standardized CSS custom properties.

Tokens Overview

Web Expressive organizes design tokens across 7 core categories:

Category Stylesheet Source Description Token Prefix
Color schemes/[scheme].css Accessible color roles mapped via light-dark() --sys-color-*
Typography core.css 30 typescale shorthand font tokens (15 baseline, 15 emphasized) across 5 roles --sys-typescale-*
Elevation core.css 6 elevation levels represented by CSS box-shadow values --sys-elevation-*
Motion core.css Expressive motion curves, durations, and focus-ring motion tokens --sys-motion-* / --focus-ring-motion-*
Measurement Space core.css 18-step spacing scale based on an 8px unit --sys-measurement-space-*
Shape Corners core.css 10 corner radius tokens from sharp (0px) to pill (9999px) --sys-shape-corner-*
Abstract Shapes shapes/clip-tokens.css 35 organic and geometric clipping and masking paths --sys-shape-clip-* / --sys-shape-mask-*

Composing System Tokens in Custom CSS

/* A custom card built entirely by composing system tokens. */
.card {
  background: var(--sys-color-surface-container);
  color: var(--sys-color-on-surface);
  border: 1px solid var(--sys-color-outline-variant);
  border-radius: var(--sys-shape-corner-medium);
  padding: var(--sys-measurement-space-300);
  gap: var(--sys-measurement-space-150);
  box-shadow: var(--sys-elevation-level-1);
  transition:
    box-shadow var(--sys-motion-spring-fast-effects-duration) var(--sys-motion-spring-fast-effects),
    transform var(--sys-motion-spring-fast-spatial-duration) var(--sys-motion-spring-fast-spatial);

  &:hover {
    box-shadow: var(--sys-elevation-level-2);
    transform: translateY(-2px);
  }
}

.title {
  font: var(--sys-typescale-title-large);
}

.supporting-text {
  font: var(--sys-typescale-body-medium);
  color: var(--sys-color-on-surface-variant);
}

Color

Per Material 3 guidelines, color roles are like the "numbers" in a paint-by-number canvas. They're the connective tissue between elements of the UI and what color goes where. These roles are implemented in design and code through tokens.

Web Expressive uses CSS custom properties with built-in light-dark() to represent these tokens.

Color roles are organized into groups: primary, secondary, tertiary, error, surface, and outline, along with optional add-on roles for fixed accents, bright and dim surfaces, and utility elevation.

General Concepts

Helpful-to-know terms used in color role names:

  • Surface – A role used for backgrounds and large, low-emphasis areas of the screen.
  • Primary, Secondary, Tertiary – Accent color roles used to emphasize or de-emphasize foreground elements.
  • Container – Roles used as a fill color for foreground elements like buttons. They should not be used for text or icons.
  • On – Roles starting with this term indicate a color for text or icons on top of its paired parent color (for example, on primary is used for text and icons against the primary fill color).
  • Variant – Roles ending with this term offer a lower emphasis alternative to its non-variant pair (for example, outline variant is a less emphasized version of the outline color).

Pairing and Layering Colors: The color system is built on accessible color pairings. These color pairs provide an accessible minimum 3:1 contrast. To ensure accessible visual contrast in your app, apply colors only in the intended pairs or layering orders. Combining colors improperly may break contrast necessary for visual accessibility. 

.card {
  background: var(--sys-color-surface-container);
  color: var(--sys-color-on-surface);
  border: 1px solid var(--sys-color-outline-variant);
}

Use primary roles for the most prominent components across the UI, such as the FAB, high-emphasis buttons, and active states.

Outline

There are two outline colors to be used against a surface:

Token Description
--sys-color-outline Important boundaries, such as a text field outline
--sys-color-outline-variant Decorative elements, such as dividers, and when other elements provide 4.5:1 contrast

Applying Outline Colors:

  • Don't use the outline color for dividers since they have different contrast requirements. Instead, use outline variant.
  • Don't use the outline color for components that contain multiple elements, such as cards. Instead, use outline variant.
  • Don't use the outline variant color to create visual hierarchy or define the visual boundary of targets. Instead, use the outline color or another color providing 3:1 contrast with the surface color.

Add-on Color Roles

Most products won't need to use these add-on color roles. However, some products require the greater flexibility and control that add-on roles provide. If you aren't sure whether your product should use the add-on roles, it probably shouldn't and you can ignore them.

Fixed Accent Colors

Primary fixed, secondary fixed, and tertiary fixed are fill colors used against surface. These colors maintain the same tone in light and dark modes, as opposed to regular container colors, which change in tone between these modes. The fixed color role may be used instead of the equivalent container role in situations where such fixed behavior is desired.

The primary fixed dim, secondary fixed dim, and tertiary fixed dim roles provide a stronger, more emphasized tone relative to the equivalent fixed color. They may be used where a deeper color but the same fixed behavior is desired.

On fixed colors are used for text and icons which sit on top of the corresponding fixed color. On fixed variant colors are used for text and icons needing lower emphasis against the corresponding fixed color.

Token Description
--sys-color-primary-fixed Fill color used against surface; maintains the same tone in light and dark modes
--sys-color-primary-fixed-dim Stronger, more emphasized tone relative to primary fixed; same tone in light and dark modes
--sys-color-on-primary-fixed Text and icons which sit on top of the primary fixed color
--sys-color-on-primary-fixed-variant Text and icons needing lower emphasis against the primary fixed color
--sys-color-secondary-fixed Fill color used against surface; maintains the same tone in light and dark modes
--sys-color-secondary-fixed-dim Stronger, more emphasized tone relative to secondary fixed; same tone in light and dark modes
--sys-color-on-secondary-fixed Text and icons which sit on top of the secondary fixed color
--sys-color-on-secondary-fixed-variant Text and icons needing lower emphasis against the secondary fixed color
--sys-color-tertiary-fixed Fill color used against surface; maintains the same tone in light and dark modes
--sys-color-tertiary-fixed-dim Stronger, more emphasized tone relative to tertiary fixed; same tone in light and dark modes
--sys-color-on-tertiary-fixed Text and icons which sit on top of the tertiary fixed color
--sys-color-on-tertiary-fixed-variant Text and icons needing lower emphasis against the tertiary fixed color

Bright and Dim Surface Roles

There are two add-on surface roles: surface dim and surface bright. While the default surface color automatically inverts between light and dark modes (it's a light color in light mode and it flips to a dark color in dark mode), the surface bright and surface dim colors keep their relative brightness across both light and dark modes.

Token Description
--sys-color-surface-dim Dimmest surface color in light and dark modes
--sys-color-surface-bright Brightest surface color in light and dark modes

Typography

The Material 3 Expressive type scale consists of 30 type styles: 15 baseline styles and 15 emphasized styles. Both style sets follow the same scale across five distinct roles: Display, Headline, Title, Body, and Label, each available in Large, Medium, and Small.

For interactive specifications, variable font axes, and language considerations, explore the official Material Design 3 Typography Documentation.

Style Roles & Hierarchy

Roles describe the functional purpose and context of text across layouts:

  • Display (Large, Medium, Small) – As the largest text on the screen, display styles are reserved for short, important text or numerals. They work best on large screens and can accommodate expressive or brand-forward typefaces.
  • Headline (Large, Medium, Small) – Best-suited for short, high-emphasis text on smaller screens, marking primary passages of text or key regions of content.
  • Title (Large, Medium, Small) – Smaller than headline styles, titles are used for medium-emphasis text that remains relatively short (such as section dividers, dialog headers, or category labels).
  • Body (Large, Medium, Small) – Used for longer passages of reading text throughout your interface. Body styles are optimized for sustained legibility at smaller sizes; avoid decorative or script fonts for body text.
  • Label (Large, Medium, Small) – Utilitarian styles used for text inside interactive components (such as buttons, chips, and navigation items) or very small metadata, such as captions and timecodes.

When to Use Baseline vs. Emphasized Styles

Use baseline and emphasized type styles together to achieve expressive experiences:

  • Baseline styles serve as the standard typographic default for all components, long-form content, and everyday layout elements.
  • Emphasized styles were introduced in the M3 Expressive update. They have a higher weight than baseline styles and can be used for selection, actions, headlines, and other editorial treatments.
  • Components: Use emphasized styles to communicate importance or active status, such as primary action buttons, Extended FABs, selected list items, selected menu items, unread messages, or badges.
  • Weight & Context: Apply emphasized styles to draw attention to specific aspects of components or text that is already bolded for greater stylistic expression.

Implementation Note: Web Expressive packages each typescale into a single CSS font shorthand token (bundling font-weight, font-size/line-height, and font-family). Always consume typescale variables via the shorthand font property. Tracking is not included in these shorthand tokens; use letter-spacing separately when needed. 

/* Standard content uses baseline styles */
.headline {
  font: var(--sys-typescale-display-small);
}

/* Expressive hero headlines use emphasized styles */
@scope (.hero) {
  .headline {
    font: var(--sys-typescale-emphasized-display-large);
  }
}

Elevation

Elevation is the distance between two surfaces on the z-axis. Material uses six levels of elevation, from 0 to 5. An element's resting state can be on levels 0 to 3, while levels 4 and 5 are reserved for interaction states such as hover and dragged.

Web Expressive represents these levels through CSS box-shadow values. Apply a token with the box-shadow property; --sys-elevation-level-0 has the value none.

Tip: Elevation shadows automatically adapt to the user's OS preference via @media (prefers-color-scheme: dark). To force or toggle modes, use [data-mode="light|dark"] or .light-mode / .dark-mode. See Handling Modes in the Theming section. 

.elevated-card {
  box-shadow: var(--sys-elevation-level-1);
}
Tokens Resting Component Examples
--sys-elevation-level-0 Filled, tonal, and outlined buttons; button groups; filled and outlined cards.
--sys-elevation-level-1 Elevated buttons, cards, and chips; modal bottom sheets, navigation drawers, and side sheets.
--sys-elevation-level-2 Scrolled app bars, menus, navigation bars, rich tooltips, and toolbars.
--sys-elevation-level-3 FABs, extended FABs, modal dialogs, date pickers, time pickers, and search.
--sys-elevation-level-4 Not assigned as a resting level. Reserved for interaction states.
--sys-elevation-level-5 Not assigned as a resting level. Reserved for interaction states.

Motion

Spatial springs are used for movement, rotation, size, and rounded corners. Effects springs are used for color and opacity, where there should be no overshoot. Each has three speeds: fast, default, and slow.

Web Expressive uses Material's recommended web curves and durations to approximate expressive springs for animations without interruptions or gestures. Apply the curve and its companion duration in a CSS transition or animation. 

.interactive-element {
  transition:
    transform var(--sys-motion-spring-fast-spatial-duration) var(--sys-motion-spring-fast-spatial),
    opacity var(--sys-motion-spring-fast-effects-duration) var(--sys-motion-spring-fast-effects);
}

Components Guide

Web Expressive components implement Material 3 Expressive interaction patterns using native HTML and modern CSS with zero runtime JavaScript.

Components Overview

Web Expressive provides a curated set of high-impact, highly configurable UI primitives. Rather than replicating an exhaustive catalog, the library focuses on essential building blocks. Any components outside this set can be built by composing Web Expressive design tokens.

All action buttons (Button, Icon Button, FAB, and Extended FAB) support both <button> and <a> elements. Selection controls (Toggle Button, Toggle Icon Button, and Switch) use native input primitives with browser-managed state.

Button

Buttons communicate actions that people can take across dialogs, modals, forms, cards, and toolbars. Can be implemented using <button> for page actions or <a> for navigation links.

Choosing Buttons & Hierarchy (M3 Specification)

When choosing a button style, consider the level of emphasis required by the action:

  • Filled (High Emphasis, Default): Uses the primary color palette. The filled button has the most visual impact after the FAB and should be reserved for final or unblocking actions in a flow (such as Save, Confirm, or Done). Use sparingly—ideally one prominent primary action per screen.
  • Tonal (Medium Emphasis): Uses the secondary container color palette. Useful for important actions that don't distract users from the main task, or for supporting secondary actions (such as Next in an onboarding flow).
  • Elevated (Medium Emphasis): Features a secondary container fill and drop shadow (elevation 1). Use only when a button requires visual separation from a patterned or visually prominent background.
  • Outlined (Medium Emphasis): Features a container stroke with no fill at rest. Ideal for actions that need attention but aren't the primary action (such as See all or Add to cart), or for providing escape actions (like Cancel).
  • Text (Low Emphasis): Has no outline or container at rest. Best used for lowest-priority actions not essential to the user journey, such as actions inside dialogs, cards, or snackbars where a visible container would distract from nearby content.
  • Export path: components/button.css
  • Base class: .button
  • Modifiers:
    • Variants: .filled (default), .tonal, .outline, .elevated, .text
    • Sizes: .extra-small (32px), .small (40px, default), .medium (56px), .large (96px), .extra-large (136px)
    • Shape: .round (default), .square
<!-- Primary filled action button (filled & small are implicit defaults) -->
<button class="button">Action</button>

<!-- Tonal button with leading icon -->
<button class="button tonal extra-large">
  <span class="icon" aria-hidden="true">stars</span>
  Get Started
</button>

<!-- Navigation link styled as an outlined button -->
<a href="/docs" class="button outline medium">Documentation</a>

Implementation Notes

Icons

Buttons, toggle buttons, icon buttons, toggle icon buttons, FABs, and extended FABs accept Material Symbols, inline SVGs, and <img>. All formats must use the .icon class. Icons are filled by default; add .no-fill for outlined icons. Use .selected for icons that appear only while a toggle input is checked.

Container Style Queries (Zero-JS Declarative Configuration)

Web Expressive components have built-in Container Style Query listeners compiled directly into their CSS stylesheets. You do not need to implement or write container queries yourself.

The core problem they solve is declarative component configuration without runtime JavaScript: when you want child buttons, toggle buttons, or icon buttons to automatically adapt their size (extra-small to extra-large), shape (round or square), or width (narrow to wide) across responsive breakpoints or container widths, you simply declare registered custom properties on the parent container element: 

/* Declarative container configuration: child components adapt with zero JavaScript */
.toolbar {
  @media (width >= 840px) {
    --size-items: large;
    --shape-items: square;
    --width-items: wide;
  }
}

Scoped to Immediate Children: These container properties affect only immediate child components within the container, preventing unwanted style leaking into deeper nested layouts.

Explicit Modifiers Win: Any modifier class added directly to a component (like <button class="button extra-large">) takes precedence over container rules.

Components that do not support a property simply ignore it. The registered properties and supported components are:

Custom Property Syntax & Values (Default) Supported Components
--size-items extra-small | small | medium | large | extra-large (default: small) .button, .toggle-button, .icon-button, .toggle-icon-button,
.fab (small, medium, large only),
.extended-fab (small, medium, large only)
--shape-items round | square (default: round) .button, .toggle-button, .icon-button, .toggle-icon-button
--width-items narrow | normal | wide (default: normal) .icon-button, .toggle-icon-button
